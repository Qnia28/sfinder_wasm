# 원래 CP 품질 묶음을 유지하는 증명 재사용

## 결과와 결정

LUNA가 기존 native 26/JS 12/oracle 25/부분 증명 8 및 새 모델 비교 18개를 통과한 뒤 105회를 완료했다. 모델 비교는 hint를 제외한 공통 단계 proto 일치를 확인했다. Astra가 174개 파일 해시와 raw/log, 원본 K/커버/품질/stable keys, 전달 prefix와 고정 가중 목표, 완료 CP 단계 objective/bound를 재검산했다. 결과는 EXACT 100, INCOMPLETE 5, 오류/완료 해답 불일치 0이다. 감사 자료는 측정 폴더의 `audit-results.mjs`, `ASTRA_AUDIT.json`이다.

재사용 없음 35/35, 개별 등식 30/35, 원래 묶음 유지 35/35 exact였다. 개별 등식의 ordinary T 5회만 미완료였다. 묶음 유지는 per-save I/T의 대응쌍 중앙값에서 각각 약 0.57/0.36초 빨랐지만, ordinary I/T에는 큰 시간 변동이 있어 평균 가속을 일반화하지 않는다. ordinary T의 대응쌍 중앙값은 약 0.65초 개선, 평균은 약 3.96초 악화로 방향도 달랐다.

**개별 등식 재사용은 이후 후보에서 제외하고, 원래 묶음 유지 방식만 선택적 재사용 후보로 남긴다.** 제품 기본 재사용은 계속 off다. 모델 형태 조정은 여기서 마무리하고 새 보드 그룹에서 엔진 전환 후보의 일반화/회귀를 확인한다. 다음 [행렬 추출 계약](SECONDARY_NEW_BOARDS_20260926.md)은 secondary 성능 측정 전에 입력을 고정하기 위한 단계다.

첫 재사용 실험은 정확했지만 성능 개선이 일관되지 않았다. 다음 후보는 원래 CP의 목표 묶음과 등식 표현을 유지한다. 구현은 `D:/AI/sfinder-wasm/tools/validation/secondary-proof-batches-20260926/cp-model.mjs`에 있으며 제품 호출 경로는 바꾸지 않는다.

## 방법

- 제어군: 재사용 없이 품질 묶음을 풀고 기수 가중 정수 objective를 등식으로 고정한다.
- 첫 재사용군: 증명된 모든 목표를 개별 등식으로 고정하고 prefix 직후부터 다시 묶는다.
- 새 후보: 원래 묶음 전체가 증명됐을 때만 같은 기수 가중 등식을 직접 추가한다. 남은 묶음 경계는 유지한다.

각 건수는 0..원본 행 수, 기수는 원본 행 수+1이다. 기수 가중값이 건수 벡터를 유일하게 나타내므로 이를 고정하는 것은 해당 건수들을 고정하는 것과 동등하다. 기존 2^45 상한/safe integer 검사, 중복 원본 행 가중치와 stable-ID 계약을 유지한다.

묶음 크기 3/prefix=4라면 처음 3개만 재사용하고 남은 증명 1개는 사용하지 않는다. prefix=1이면 재사용하지 않는다. 모든 품질이 증명됐다면 마지막 짧은 묶음도 통째로 재사용하지만 stable-ID tie는 반드시 증명한다. 모델 형태가 같아도 중간 seed/hint가 달라질 수 있어 동일 탐색·속도를 보장하지 않는다.

## 검증

이전 검증된 native/WASM snapshot을 그대로 복사한다. 기존 native 26/JS 12/oracle 25/부분 증명 검증을 유지하고, 새 batch-tests에서 독립 oracle, prefix 0/1/2/3/4/5/전체, 묶음 크기 2/3, 전체 품질 후 tie를 검사한다. 공통 단계의 모델 proto는 solutionHint만 제외하고 대조하며 직접 고정한 목표를 BigInt로 검산한다. 새 테스트는 아직 실행하지 않았다.

통과하면 이전 CP 완료 입력 7개×세 조건×5회=105회 측정한다. integrated100k→threshold20k→CP 1-worker, 전체 목표 60초/외부 종료 65초, fresh process 직렬 실행이다. 같은 WASM/proof/입력으로 완료율, 입력별 시간 분포, availableThresholds/reusedThresholds, proofLocks 및 품질/tie 비용을 비교한다.

이전 heldout 미완료 1개와 CP 미호출 2개는 이번 모델 형태 진단에서 제외한다. prefix=1인 per-save Z는 재사용 없는 대조 사례로 유지한다. 이것은 일반화 검증이 아니며 제품 적용 전에는 제외 입력과 다른 보드 그룹을 포함한다.

ordinary I/T 회귀 해소와 다른 입력의 회귀 여부를 우선 판단한다. 효과가 불충분하면 재사용 기본 적용을 보류하고 모델 변형을 계속 늘리지 않는다. 엔진 우선순위 확정과 per-save worker 배분은 후속 작업이다.
