# Exact secondary 세션 재사용 — P2 최소 구현

2026-09-22. P1의 순차 분해에서 엔진을 전환할 때 재준비와 완료 성분의 재증명을 줄이는 내부 실행 계층이다. 자동 분해는 여전히 off이며 기존 기본 경로의 integrated 100,000 상태 → threshold 정책은 유지한다.

## 구현

`createSecondarySession(coverage, options).run({ solver, engine, stateBudget })`를 추가했다.

- 최소 K 증명을 전제로 원본 CSR과 key 배열을 한 번 소유 복사한다. 외부에서 원본 버퍼를 바꾸더라도 저장된 증명은 영향을 받지 않는다.
- 연결 구조, 성분별 K, 로컬 수치 행렬 및 feasible incumbent를 세션 안에서 재사용한다.
- `completed: true`인 성분만 완료 증명으로 저장한다. 다음 호출에서는 해당 성분의 solver 호출을 생략한다.
- 미완료 성분에는 이전 feasible seed를 전달한다. 예산은 매 호출마다 필터 전체에서 차감하며, 호출별 상태 수를 별도로 반환한다.
- 모든 성분이 완료됐으면 원본 품질 벡터도 저장한다. 반환 배열은 복사하여 호출자의 결과 변경이 증명을 바꾸지 못하게 한다.
- solver 선택 결과의 후보 수·성분 소속·원본 행 커버를 검증한 뒤에만 상태를 갱신한다.
- 증명은 세션 내부에만 존재한다. 다른 입력/필터의 반환 객체에서 증명을 가져오거나 전역 캐시에 저장하지 않는다.

`solveStructuredSecondary`는 한 번 실행하는 호환 진입점이다. `solveExactSecondary`의 내부 `decomposition: 'on'` 경로는 같은 호출 안에서 integrated → threshold로 바뀔 때 세션을 유지한다.

반환 진단에는 `preparedComponents`, `reusedComponents`, 성분별 `reusedProof`를 추가했다. 이 값은 준비된 성분 수와 재사용된 전체 증명을 뜻한다. threshold의 일부 품질 단계 증명이나 DFS 상태의 재개를 뜻하지 않는다.

## 범위와 비용

WASM 내부 행렬/전처리와 DFS stack은 계속 엔진 호출마다 준비한다. threshold prefix 전달과 bounded continuation, worker 사이의 세션/증명 이전은 미구현이다. 부모의 `deferThreshold`로 worker에 넘기는 경우에는 기존대로 입력과 incumbent만 전달하며 세션은 새로 만든다.

입력 불변성을 보장하기 위한 최초 복사와 선택 결과 검증에는 비용이 있다. 특히 한 번의 짧은 탐색으로 끝나는 입력은 재사용 이득이 없을 수 있다. 해당 비용 때문에 이 기능을 기본 전체 실행 경로에 추가하지 않았으며, 자동 분해도 활성화하지 않았다.

## 정확성

- 작은 행렬 80개의 완전탐색 참조 × 두 엔진 × 세 분해 설정에서 K/품질/stable key 일치를 유지했다.
- 완료 성분만 건너뛰는지, 미완료 성분에 같은 행렬과 seed를 전달하는지, 원본/반환 배열 변경과 다른 세션이 증명을 오염시키지 않는지 검사했다.
- 잘못된 solver 선택이 저장된 완료 증명이 되지 않는지 검사했다.
- 프로젝트 JS: 120 통과 / 0 실패 / 조건부 baseline batch 검사 1개 skip. 공통 exact 함수의 integrated → threshold 전환에서 같은 성분 행렬과 완료 증명을 실제로 재사용하는 통합 회귀도 포함한다.
- 외부 269개 검사 중 초기 실행의 1개 정적 검사에서 지역 동기 세션의 `??=` 문법이 promise-cache 금지 규칙에 걸렸다. 동일 의미의 명시적 `if`로 바꾸고 해당 묶음 10개와 신규/worker 회귀 15개를 재실행하여 25/25 통과했다. 초기 나머지 외부 검사는 통과했다.
- Rust/WASM 소스·바이너리는 변경하지 않았다.
