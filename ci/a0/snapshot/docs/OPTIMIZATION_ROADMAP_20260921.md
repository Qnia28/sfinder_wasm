## 목표와 원칙

최소 K, 큐별 품질의 정렬 벡터, stable-ID 동률 선택, 출력 순서 및 save 의미를 보존하면서 전체 명령 시간을 줄인다. 쉬운 입력의 지연 증가, 느린 입력의 최악 지연, 메모리 증가도 함께 관리한다.

- minimals와 per-save는 같은 공통 최적화 정책을 사용한다. 명령 이름 자체를 분해/엔진 선택의 근거로 사용하지 않는다.
- 분해는 선택 가능한 실행 경로다. 분해하지 않는 경로와 소수 성분을 묶는 경로도 유지한다. 여러 성분이 존재한다고 자동으로 각각 solver를 호출하지 않는다.
- 알고리즘 개선을 순차 실행에서 먼저 검증한 뒤 병렬화 효과를 별도로 측정한다.
- 초기에는 primary와 후보 열거를 유지하고, 이미 증명된 K 이후의 secondary부터 변경한다. primary 자체의 성분 분해는 후속 실익이 있을 때 별도 검증한다.
- 기존 saves outcome-only를 유지한다. minimals에는 기하 해답과 정확한 orderCount가 필요하므로 saves 결과로 대체할 수 없다.
- CP-SAT 최적 모델과 전체 탐색 상태 재개 기능을 모두 완성할 때까지 첫 개선의 적용을 미루지는 않는다. 작은 단위로 검증·통합한다.

## 기준 입력과 측정 설계 — P0

카탈로그는 다음 세 파일을 사용한다.

- `D:/AI/tetrispc/setups/cycle-1-setups.json`
- `D:/AI/tetrispc/setups/cycle-3-extra-t-setups.json`
- `D:/AI/tetrispc/setups/QB/cycle-7-2plus2-qb-setups.json`

456개 항목, 같은 점유 보드 338종, 반전까지 묶은 297그룹이라는 기존 조사를 재사용한다. 같은 보드·동일 큐/필터의 반복 항목은 중복 집계하지 않는다. 좌우 반전은 검증 표본 분리 단위이며, 비대칭 큐/필터까지 같은 입력이라고 생략하지 않는다.

4×4 BOX `*!` exact는 이름이 아닌 점유 모양으로 제외한다(13개 카탈로그 항목). 기존 3×4 BOX 8P 및 모바일 제외도 유지한다. 서로 다른 패턴의 BOX까지 같은 이유로 자동 제외하지 않으며 실행 대상은 manifest에 명시한다.

1. 기존 per-save 54행렬과 일반 minimals 16행렬을 회귀 corpus로 사용한다.
2. 카탈로그에서 필요 미노 수, 후보/큐/연결 수, K, 품질 단계, 행 중복률, 성분 수·최대 크기가 다양한 표본을 확대한다. 일반 minimals는 단일 미노뿐 아니라 결합/부정/중복 미노 필터도 포함한다. per-save는 가능한 7개 미노를 모두 포함한다.
3. `*!`, 제한 분할 `[IJL]p3,*p4`, 독립 `*p3,*p4`를 별도 조건으로 유지한다. 큐가 짧아 해답이 없는 경우 난도 자료에서 분리한다. cycle별 실전 큐는 명시된 입력이 있을 때 별도 추가하며 이름에서 추측하지 않는다.
4. 기존에 조사한 보드 그룹은 개발용으로 취급한다. 새 그룹 일부를 측정 전에 검증용으로 고정하고, 같은 보드/반전이 양쪽에 섞이지 않게 한다. 검증용 결과를 보고 규칙을 수정하면 새 검증 표본을 확보한다.

측정 구간: 패턴 준비 → 후보 열거 → 필터 행렬 구성 → primary → secondary 준비 → 탐색/증명 → 동률 증명 → 결과 복원/전송. 탐색 노드 수는 보조 지표이며 알고리즘 간 같은 작업량이라고 취급하지 않는다.

secondary 단독 비교는 동일 행렬·K·seed를 사용한다. 기존 운영 정책, 각 단독 엔진, 새 혼합 정책도 비교한다. 성능 측정은 한 번에 한 조건씩 수행하며 동시 테스트로 인한 CPU 경합을 피한다. 순서를 교대하여 우선 3회 측정하고 경계/변동 사례는 5회 이상 확인한다. cold 초기화와 재사용된 worker/모델 시간은 분리한다.

초기 난도 분류는 짧은 제한으로 수행하되, 결론에 필요한 미완료 표본만 단계적으로 더 긴 예산을 준다. 열거·primary 시간 초과와 secondary 미완료는 구분하며, timeout을 실제 완료 시간으로 대입하거나 실패율에서 제거하지 않는다.

**산출물:** 버전·입력 hash가 있는 corpus manifest, 단계별 시간/메모리 기록, exact 참조 결과, 개발/검증 그룹 목록.

## 안전한 즉시 완료와 선택적 분해 — P1

대상: `min-cover-exact-secondary.mjs`와 새 공통 구조 분석 모듈. 초기 실험은 JS에서 가능하되, 반복적인 포장 비용이 실측되면 원본 CSR을 직접 처리하는 Rust API로 이동한다. 어느 명령에서도 동일한 진입점을 사용한다.

### P1a: 자명한 exact 처리

- 빈 문제, 사용 후보 전체를 선택하는 K, 원본 singleton 행으로 강제되는 후보 F만으로 모든 행을 덮고 `|F|=K`인 경우를 처리한다.
- 여기서 후보 수는 필터 행렬에 실제 등장하는 후보 수다. 전체 기하 후보 수와 구분한다.
- primary dominance 이후 만들어진 kernel의 forced 목록은 원본 강제 선택의 증거로 사용하지 않는다.
- 원래 품질 벡터와 stable-ID/출력 순서를 복원한다. 자명한 처리를 전체/분해 경로 양쪽에 동일하게 적용하여 분해 효과와 혼동하지 않는다.

### P1b: 분해 검사와 실제 실행 분리

원본 행렬의 모든 후보–큐 연결로 union-find를 수행한다. 준비 비용은 연결 수에 거의 비례한다. 구조만 검사할 때 모든 성분의 행렬 사본을 만들지 않고 row/candidate index와 통계만 보존한다.

선택지는 다음 세 가지다.

| 경로 | 적용 판단에 사용할 정보 |
|---|---|
| 전체 문제 유지 | 이미 매우 짧음, 연결 성분 하나, 분해 준비 비용 대비 작은 이득 |
| 독립 성분별 순차 실행 | 큰 문제를 여러 작은 탐색으로 줄일 수 있음, 선택 조합의 결합이 큰 경우 |
| 작은 성분 묶음 + 큰 성분 | 작은 solver 호출이 너무 많거나 큰 성분 하나가 대부분을 차지하는 경우 |

같은 성분들이 독립이라는 사실만으로 속도 향상을 보장하지 않는다. 특히 전체 600개 후보가 590+10개로 나뉘는 입력과 다수 singleton 입력을 별도 회귀군으로 둔다. 큰 성분 비율 하나만으로도 결론내리지 않는다. 남은 K, 강제 선택 비중, 연결 밀도, 품질 단계 및 준비 시간이 함께 영향을 준다.

증명된 전역 K와 feasible K-seed를 각 성분에 나누면 각 성분의 최소 K를 얻는다. 성분별 품질 histogram과 최종 선택을 합쳐 전역 exact를 복원한다. 원래 전역 ID의 순서를 로컬 ID 변환에서도 유지한다. 이 방식은 최소 K가 아닌 임의 고정 개수 문제에 일반화하지 않는다.

### P1c: 분해의 순수 효과 검증

동일한 엔진·seed·즉시 완료 규칙에서 전체와 순차 분해를 비교한다. 성분별 10만 상태를 주면 전체 예산이 성분 수만큼 늘어나므로, 제한 탐색에서는 필터 전체 누적 예산도 고정한다. 무제한 exact 완료 시간 비교와 제한 예산 비교를 별도로 기록한다.

분해 후 엔진 선택을 바꾸는 실험은 그 다음에 한다. 기존 시제품의 개선에는 분해, 자명한 처리, 성분별 예산 변화가 함께 포함되어 있으므로 이를 순수 분해 효과로 해석하지 않는다.

**통과 조건:** 작은 완전탐색·실제 참조 결과와 K/품질/ID 일치, 동률/중복 행/분해 불가/불균형 분해 검증, 준비·병합을 포함한 시간에서 이득 확인. 느려지는 표본은 원인에 따라 전체 실행 또는 묶음 경로로 보내는 기준을 만들고 별도 표본에서 재검증한다.

## 공통 행렬·예산·증명 상태 계약 — P2

대상: `pc-wasm-cover-matrix.mjs`, `pc-wasm-min-cover.mjs`, Rust min-cover ABI 및 exact 실행 계층.

### 먼저 구현할 최소 범위

- 요청/worker 내 원본 CSR, 전역↔로컬 ID, 중복 큐 가중치 및 분석 통계를 재사용한다. 각 엔진의 특수 전처리는 그 엔진을 실제 사용할 때 생성한다.
- 결과 상태를 `feasible incumbent`, `cardinality proven`, `quality prefix proven`, `quality proven`, `stable tie proven`으로 구분한다. 기존 공개 응답의 exact 계약은 유지한다.
- 같은 입력·필터·K·품질 단계 체계를 식별할 fingerprint를 증명 상태에 붙인다. 근사 해의 품질을 증명된 target으로 고정하지 않는다.
- 단계별 반환에 경과시간, 상태 수, 최선해 개선, 완료된 품질 단계, 상한 정보(있는 경우)를 제공한다. integrated에 아직 전역 품질 bound가 없으면 gap 수치를 만들어내지 않는다.
- 후보 ≤48의 무제한 legacy 경로를 공통 예산에 포함한다. tiny 경로의 정확한 기본 범위는 측정 후 결정하며 최종 exact를 포기하는 fast fallback으로 바꾸지 않는다.

### 후속 범위

threshold가 완료한 prefix/targets를 반환하고 bounded continuation에서도 받을 수 있게 한다. 먼저 전처리와 완료된 단계의 재증명을 피하고, DFS stack/memo까지 보존하는 완전한 재개 기능은 반복 재시작 비용이 클 때 추가한다.

WASM 동기 호출은 JS 타이머만으로 중간 취소할 수 없다. 상태 예산과 관측된 상태당 비용을 이용하는 짧은 호출 또는 Rust의 주기적인 host-clock 확인을 비교한다. 전처리 시간도 예산에서 누락하지 않는다. 실제 작업 위치를 바꾸는 전환에는 데이터 전송/새 runtime 준비 비용을 포함한다.

**통과 조건:** 예산 종료 후 incumbent 유효성, 재개와 처음부터 실행의 exact 일치, 다른 행렬의 prefix 거부, 완료 전 exact 오표시 방지, 메모리 해제/재사용 검증.

## 엔진 자체 개선과 선택 정책 — P3

### P3a: integrated를 독립적으로 개선·비교

현재 integrated의 완성 해 histogram 최적화는 유지한다. 다음 변경은 각각 별도 스위치로 비교한다.

1. pivot의 형제 분기에서 앞선 후보를 제외하여 동일 선택 집합으로 가는 중복 경로를 줄인다. 전체 ID 단조 증가만 강제하는 방식은 사용하지 않는다.
2. 현재 선택과 남은 후보로 얻을 수 있는 낙관적인 품질 상한을 이용한다. 상한이 incumbent보다 낮을 때만 안전하게 제거하며 동률 후보의 stable-ID 개선 가능성을 보존한다.
3. 상한 계산 자체가 비싼 작은 문제에서는 생략한다. 각 최적화의 탐색 감소와 상태당 비용 증가를 함께 측정한다.

전체/분해 × 기존/개선 integrated를 비교한다. 기존 threshold의 그룹화·dominance, integrated histogram 등을 새로 구현한 효과로 중복 보고하지 않는다.

### P3b: 세 엔진의 역할과 전환

2026-09-23 순서 보완: [routing 반복 검증](SECONDARY_ROUTING_EXPERIMENT_20260922.md)에서 짧은 probe 미완료만으로 threshold에 전환하면 integrated가 곧 완료할 사례를 놓치는 퇴보를 확인했다. 구조 선확인 후 성분이 적으면 단일 integrated 호출의 기존 예산을 유지하는 후보를 추가 비교한다. 탐색 상태 수 감소를 시간 감소로 간주하지 않는다. 검증셋에서 실제 분해 후 완료된 비자명 사례가 없으면 분해 정책의 일반화가 검증됐다고 판단하지 않는다.

P3a의 다음 독립 구현 범위도 구체화한다. 현재 `BestSetSearch::run`은 완료 선택 집합을 `completed`에서 중복 제거하며, `SequentialThresholdSearch`에는 이미 형제 분기 제외/복원이 있다. integrated에 같은 원리를 옮길 때는 현재 pivot의 앞선 형제만 제외하고, 부모의 제외 상태를 재귀 복귀 및 예산 소진 때 정확히 복원한다. 전역 candidate ID 증가 조건은 쓰지 않는다. case 선택은 사용 가능한 후보를 기준으로 하며, 기존 lower bound가 제외된 후보를 포함해 느슨해지는 것은 안전하지만 허위 불가능 판정은 허용하지 않는다. 초기에는 완료 집합 해시와 histogram 전환 규칙을 유지하고, 무제한/매우 작은 예산/동률/원본 중복 행/seed가 최적해인 경우를 완전탐색과 대조한다. 이 변경과 품질 상한 가지치기를 별도 비교하여 상태 감소와 상태당 비용을 분리한다. 아직 Rust 구현에는 적용하지 않았다.

고정 `integrated → threshold → CP-SAT` 순서를 전제하지 않는다. 처리할 문제가 확정된 뒤 다음 정보를 사용해 첫 엔진과 예산을 정한다.

- 실제 후보 수와 최소 K, 강제 선택을 제외한 자유 선택 규모.
- 행/연결 수, 동일 품질 행의 가중 그룹 수, 품질 단계 수.
- 분해/묶음 후 최대 문제 크기 및 준비 비용.
- 짧은 탐색에서의 incumbent 개선과 증명 진척, 관측된 시간.

초기 비교 후보는 integrated probe 없음/1천/1만/10만 상태, 시간 예산 5/20/50ms 등이다. 이는 **측정용 후보**이며 운영 상수가 아니다. 필터 전체/요청 전체의 누적 probe 예산을 함께 둔다. 한 엔진에서 개선이 없다는 사실만으로 다른 엔진의 우위를 가정하지 않는다.

CP-SAT은 단계별 목표와 안전한 정수 범위의 목표 묶음을 비교하고 1/2-worker를 구분한다. 기존 실험에서 보완한 선택 해 기반 정수 목적값 재계산을 유지한다. 모델 생성, 품질 증명, 동률 증명 시간을 나누며 품질만 증명됐다고 최종 exact로 반환하지 않는다.

전환 시 가능한 최선해와 증명된 prefix를 전달한다. 같은 엔진의 무의미한 재시작과 엔진 간 왕복을 제한한다. 최종 엔진은 증명 완료까지 지속하거나 사용자가 취소할 수 있어야 한다. 세 엔진이 모두 짧은 probe에서 미완료됐다는 이유로 근사 결과를 exact로 반환하지 않는다.

**정책 선택 기준:** 전체 정책의 준비·probe·전환 포함 시간, median/p95, 미완료 비율, 메모리 및 느려진 개별 사례. 단독 엔진보다 항상 빠르다고 보장하지 않는다. 검증 표본의 쉬운 작업에서 반복 확인되는 퇴보는 적용 범위를 좁히거나 해당 변경을 보류한다. 상세 분포 없이 가속 사례만 보고 기본값을 바꾸지 않는다.

## Per-save worker 분배 — P4

P1~P3의 순차 공통 정책이 검증된 후 진행한다.

1. 공통 후보/품질을 한 번 산출한다.
2. 필터별 원본 행렬과 대략적 작업량을 준비한다. K가 아직 없으면 분해의 구조 정보만 이용하고 K별 exact 판정은 primary 이후 수행한다.
3. 자명하거나 검증된 tiny 작업은 로컬에서 제한된 예산으로 처리한다.
4. 무거운 필터 작업을 worker로 보내 **primary → K 확정 → 선택적 분해 → secondary**를 이어서 수행한다. 부모에서 모든 필터의 integrated 10만 상태를 먼저 돌리지 않는다.
5. 큰 독립 성분만 남는 경우 공통 작업 큐에 묶음으로 재분배할 수 있게 한다. 중첩 worker pool을 만들지 않는다. 이는 첫 통합 이후 필요할 때 확장한다.

기본 비교는 worker 0/2/4개와 cold/reused pool이다. primary Rust/HiGHS 1스레드, ORTools 2-worker 설정을 유지한다. 내부 2-worker 솔버 작업은 총 CPU 슬롯 두 개를 사용하는 것으로 예산을 잡고 secondary CP-SAT도 포함한다. 슬롯뿐 아니라 행렬/런타임 메모리 상한도 고려한다.

작은 성분마다 메시지를 보내지 않는다. 전역 stable-ID를 숫자로 전달하고 geometry/Fumen 복원은 부모에 남긴다. 작업 전용 CSR은 transferable로 넘기며, 재사용해야 하는 부모 배열을 detach하지 않는다. pool 재사용은 제한된 수명·정리 정책과 함께 도입한다.

**통과 조건:** 기존 0-worker와 exact/표시 결과 일치, 초기화·복사 포함 전체 요청에서 이득, 취소·오류·재사용 시 결과 섞임 없음, 실제 Chrome Worker 및 Node 검증. 알고리즘 개선 효과와 병렬화 효과를 별도로 보고한다.

## 후보 열거와 saves 후속 개선 — P5 / S2

### P5: minimals/per-save의 넓은 큐 열거

secondary 작업과 별도로 DAG 구성, 기하 복원, 성공 순서 수집, 큐 투영, orderCount 집계를 계측한다. 열거가 15초에 막힌 전체 split은 secondary 개선으로 해결되지 않는다.

중복 순서/기하 표현의 압축과 조기 큐 호환성 적용을 검토하되, 정확한 해답별 orderCount와 원래 좌표를 보존한다. 공유 DAG를 복제하는 root 병렬화보다 재계산 제거를 먼저 비교한다. 필요 시 별도 계획을 작성하며 exact secondary 정책 구현을 무기한 막는 선행 조건으로 삼지 않는다.

### S2: saves

현재 outcome-only를 기준선으로 유지하고 Rust 탐색, 결과 전달, JS 코드 집계, 문자열 변환, 표현식 평가를 계측한다.

1. 낮은 비용의 변경부터: RegExp 사전 컴파일, 요청 내 save-code 문자열/표현식 평가 재사용.
2. `queueLength=req+1`에서는 잔여 미노 u8 전송과 기존 packed 결과를 비교한다. 최종 save는 마지막 bag과 중복 미노를 보존하여 복원한다.
3. 실제 언어 예산 초과가 관측되면 성공한 root의 압축 결과를 유지하고 실패한 root만 exact fallback하는 구조를 검토한다.
4. ALL/지정 표현식 등 요청별 집계 경로를 비교한다. 부재 조건과 전체 outcome이 필요한 경우 첫 성공만으로 중단하지 않는다.
5. 병렬화는 개선 후에도 Rust 탐색이 지배적인 경우에만 별도 검토한다.

**통과 조건:** ALL과 지정 표현식 전체 응답, `I&&J`/`IJ`, `^I`/`!I`, `T`/`TT`, regex/alias, branch metadata, 실패 큐 순서·중복, 긴 큐, Hold on/off, complete-row 및 2~6줄 회귀 일치.

## 구현 묶음과 완료 산출물

| 순서 | 구현 묶음 | 완료 산출물 |
|---|---|---|
| 1 | P0 + P1a/P1b | 기준 corpus, 자명한 exact 처리, off/on/auto 분해 실험 경로 |
| 2 | P1c + P2 최소 범위 | 동일 엔진 순차 A/B, 분해/묶음 선택 기준, 행렬·예산·상태 계약 |
| 3 | P3a | integrated 개선별 정확성·성능 표, 채택/보류 결정 |
| 4 | P2 prefix 확장 + P3b | 세 엔진 첫 선택·전환 정책과 별도 보드 그룹 검증 |
| 5 | P4 | 필터 전체 worker 분배, cold/reuse 및 취소·메모리 검증 |
| 별도 | P5 / S2 | 넓은 큐 열거 보고서 / saves 계측 및 이득 확인된 변경 |

각 묶음에서 작은 완전탐색, 저장된 exact 행렬 대조, 실제 명령 결과, 필요한 브라우저 검증을 수행한다. 구현 스위치와 진단 수치는 내부 검증용이며 사용자가 새 설정을 알아야 기존 기능을 사용할 수 있게 만들지 않는다.

앞선 분해 시제품의 수십 ms 결과는 가능성을 보여주는 자료다. 제품 전체 요청, 같은 엔진 조건, 손해 사례를 포함한 검증을 통과해야 기본 경로에 적용한다.
